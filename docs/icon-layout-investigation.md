# Перепутанные иконки после установки плагина

Дата: 2026-09-22. Проверен Terminal 0.1.0, коммит `0ab89df2e9fd435eae585e7447ebce7229ef33f2`.

## Вывод

В локальном коде Элемента воспроизведена ошибка восстановления иконок contributed view containers при изменении порядка регистрации плагинов. Она объясняет скриншот владельца: панель XBSL.IO открывается, но слева отображается иконка другого расширения. Владелец сообщил, что это произошло после перезагрузки, сервер — 9.1.9.

Установка Terminal добавляет контейнер `xbslTerminal`. Он расположен снизу, но получает номер иконки из того же счётчика, что и боковые контейнеры. Если новый контейнер зарегистрирован перед существующими, их номера сдвигаются. Добавление в конец списка само по себе ошибку не вызывает.

Регистрация `viewsContainers` выполняется хостом по манифесту; для этого не требуется запуск Bash или активация кода терминала. Коллизий собственных идентификаторов Terminal и XBSL.IO не обнаружено. Стили терминала находятся внутри Webview, доступа к DOM родительской IDE в коде нет. Манифест не регистрирует темы или общие наборы иконок.

Это подтверждение дефекта на локальном коде ветки 9.1.9, а не окончательная диагностика удалённой сессии: её DOM, сохранённая раскладка, точный build сервера и фактический порядок регистрации не получены.

## Механизм

1. `PluginViewRegistry.registerViewContainer` выдаёт класс вида `plugin-view-container-icon-N` из общего последовательного счётчика. CSS связывает его с URL SVG.
2. `ViewContainer.doStoreState` сохраняет класс в `title` контейнера и `originalContainerTitle` его частей.
3. После перезагрузки новые CSS-правила могут связывать старый номер с другим плагином. `doRestoreState` возвращает сохранённые заголовки.
4. `prepareViewContainer` пытается задать актуальную иконку. Однако `updateTitle` для контейнера с несколькими видимыми частями возвращает старый `originalContainerTitle`. У XBSL.IO две части: «Каталог» и «Установленные»; свёрнутая часть остаётся видимой.
5. Сохраняется неправильный номер. Следующая обычная перезагрузка может повторить ошибку.

Постоянное исправление относится к хосту: стабильные идентификаторы CSS для иконок и корректное восстановление актуальных заголовков частей. Изменение имени SVG или publisher терминала этот механизм не исправляет. Vendor-код не изменялся.

## Проверка

`scripts/check-icon-layout.mjs` читает локальный frontend bundle, извлекает и исполняет его методы регистрации, сохранения, восстановления и обновления заголовка. DOM, layout и сервисы заменены минимальными заглушками; порядок регистрации задан тестом. Скрипт не запускает IDE и не меняет её файлы или настройки. В выводе есть SHA-256 bundle и извлечённых фрагментов.

Команды из корня репозитория:

```sh
node scripts/check-icon-layout.mjs ../RnD/local-codex-docs/local-server
node scripts/check-icon-layout.mjs ~/Downloads/server-package-with-ide-9.2.4-6
```

Обе проверки прошли: по пять сценариев.

| Сценарий                                           | Результат                   |
| -------------------------------------------------- | --------------------------- |
| Восстановление без изменения порядка               | Правильная иконка           |
| Новый контейнер добавлен последним                 | Правильная иконка           |
| Новый контейнер добавлен перед существующими       | Воспроизведена чужая иконка |
| Повторное восстановление уже испорченной раскладки | Чужая иконка сохраняется    |
| Новый экземпляр контейнера и его частей            | Правильная иконка           |

В сценарии со сдвигом хост ожидает для XBSL.IO класс `plugin-view-container-icon-2`, но после восстановления остаётся `plugin-view-container-icon-1`, уже связанный с `codex.svg`. Это условные имена SVG для проверки, а не снимок регистрации удалённого сервера.

Проверенные поставки:

| Локальный источник                            | IDE package / Theia | SHA-256 frontend bundle                                            |

| `~/Downloads/server-package-with-ide-9.2.4-6` | 9.2.4-1 / 1.59.110  | `9d01c82af815daa0ea74ebe5f7dff8658f6aa218c7c52bdc7e4086c124c768d0` |

В обеих поставках прочитаны `ide/theia/products/browser-app/package.json` и `lib/frontend/bundle.js`. SHA-256 всех извлечённых методов совпали между поставками. Версия IDE package не подставляется вместо точной версии сервера.

Сходный механизм есть в исходниках upstream [PluginViewRegistry](https://github.com/eclipse-theia/theia/blob/v1.59.0/packages/plugin-ext/src/main/browser/view/plugin-view-registry.ts) и [ViewContainer](https://github.com/eclipse-theia/theia/blob/v1.59.0/packages/core/src/browser/view-container.ts). Вывод основан прежде всего на локальных поставках Элемента.

## Восстановление и проверка на стенде

Первый вариант для ручной проверки — закрыть и заново открыть затронутый контейнер через меню представлений. Для XBSL.IO в проверенном коде зарегистрирована команда `View: Toggle XBSL.IO` (название зависит от языка интерфейса), ID `plugin.view-container.workbench.view.extension.xbslMarketplace.toggle`. Первый вызов уничтожает прикреплённый контейнер, следующий создаёт его заново. Простое переключение на соседнюю иконку контейнер не пересоздаёт. Нужно проверить результат в рабочей IDE, затем перезагрузить её и проверить сохранение результата.

Если пересоздание отдельных панелей не помогает, в проверенных поставках есть штатная команда `Reset Workbench Layout`, ID `reset.layout`. Она сбрасывает расположение панелей **и тему**, затем перезагружает IDE после проверки несохранённых изменений. Это более широкий сброс; автоматически его не выполняем. Очистка всего хранилища браузера не требуется.

Для окончательного подтверждения на удалённом сервере достаточно сопоставить CSS-класс выбранной вкладки XBSL.IO, URL её `mask-image` и текущую регистрацию контейнера. Иконка должна ссылаться на ресурс marketplace, а не на другой плагин. Приватное окно с новой раскладкой также может служить контрольным сравнением, но потребует отдельного входа и не исправит исходную раскладку.

Надпись «Ожидает перезапуска IDE» не доказывает, что Terminal не загружен: в marketplace 0.1.13 `SharedHostAdapter.loadedVersion()` возвращает неизвестную версию. Сохранённое состояние `reload_required` само по себе не подтверждает фактическую активацию.

Изменены только диагностический скрипт и документация Terminal. Runtime, манифест, опубликованный архив 0.1.0, сервер и установленные плагины не изменены. Следующий шаг — ручная проверка пересоздания контейнера на стенде 9.1.9; исправление механизма хоста требует отдельного согласованного решения.
