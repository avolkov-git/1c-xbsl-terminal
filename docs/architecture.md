# Архитектура терминала

Решение владельца: запускать самостоятельный Bash из серверного Node extension host. Внешний плагин использует публичный VS Code API и Node API. Vendor bundle, launcher, конфигурацию Элемента и штатный Terminal API он не меняет.

## Компоненты

`src/extension.ts` регистрирует WebviewView в `contributes.viewsContainers.panel`. Theia размещает этот контейнер снизу. Стандартная команда фокуса открывает панель. Процесс запускается только по действию пользователя; активация и показ пустой панели не запускают Bash.

`ui/terminal.ts` содержит xterm.js и небольшую панель управления. Содержимое процесса попадает в xterm как байты, не как HTML. Webview не открывает HTTP/WebSocket-соединения; все сообщения проходят через `postMessage` публичного API. Скрипт входит в сборку, CSP использует nonce. CSS допускает inline-стили для xterm; внешние ресурсы запрещены. Ссылки, OSC-доступ к clipboard и автоматический запуск URI не добавлены.

`src/session.ts` управляет одним PTY-процессом. `bin/runtime.json` содержит фиксированные пути, размеры и SHA-256. Выбор платформы использует `process.platform` и `process.arch`. Проверка пакета предотвращает случайный запуск повреждённого файла, но не заменяет проверку доверия к издателю архива.

Go helper запускает Bash через Unix PTY (`creack/pty`) или Windows ConPTY. Он не зависит от ABI Node и не содержит `.node`-модулей. Node обменивается с helper JSON-строками через stdin/stdout; данные терминала кодируются Base64. Нет сетевого порта или отдельного сервиса. Linux-сборки используют `CGO_ENABLED=0`.

## Потоки и завершение

- Веб-интерфейс отправляет `new`, `configure`, `input`, `resize`, `ack`, `close`, `ready`.
- Host принимает ввод только для собственного известного session id, проверяет типы, размеры и диапазоны. Исполняемый файл не приходит из Webview или настройки workspace.
- Helper получает `start`, затем `input`, `resize`, `close`. Ответы: `ready`, `data`, `exit`, `error`. Протокол версии 1.
- Неподтверждённый вывод свыше 256 КиБ Base64 приостанавливает stdout helper; подтверждение ниже 128 КиБ возобновляет чтение. Это передаёт противодавление до PTY.
- Для повторного подключения Webview host хранит до 1 МиБ Base64 вывода на сессию; xterm хранит 2000 строк. Максимум восемь сессий. Скрытая отсоединённая сессия теряет старый вывод с сообщением об усечении.
- Закрытие Webview/extension останавливает сессии. EOF stdin helper также завершает Bash. Unix использует SIGHUP и закрытие PTY, затем резервный Kill Bash. Отсоединённые пользователем Unix-процессы не входят в гарантию завершения.
- Windows helper помещает себя и потомков в Job Object с `KILL_ON_JOB_CLOSE`. Эта ветка скомпилирована, но требует нативного теста в окружении Element, включая вложенный job сервера.

Рабочий каталог берётся из активного локального workspace; при нескольких корнях есть выбор. Без workspace используется домашний каталог серверной учётной записи. Нефайловый workspace даёт ошибку. Сессии имеют права и окружение Node host, не права отдельного браузерного пользователя. Администратор согласует допуск к консоли на многопользовательском сервере.

## Поставка и границы совместимости

Пакет содержит xterm.js, addon-fit и шесть PTY-бинарников (Linux/Windows/macOS × x64/arm64). Helper получает Bash из системы; загрузки оболочки, npm/go install на хосте и телеметрии нет. Пользовательские startup-файлы Bash выполняются по обычным правилам оболочки.

Для публикации на XBSL.IO используйте ZIP как universal-артефакт. Манифест содержит `xbsl` v1, `requiredFiles` и `dependenciesBundled: true`. SHA-256 архива находится в соседнем файле `.sha256`. Плагин проверяет размер и SHA-256 выбранного PTY; в Unix он восстанавливает режим `0755`, если у бинарника отсутствует право исполнения владельцем. Для этого учётной записи host нужно право изменить режим файла.

Скрытие панели сохраняет сессии, пока host сохраняет Webview. Закрытие Webview или завершение extension host останавливает сессии; после перезагрузки IDE нужно создать новую. Плагин не сохраняет стенограмму на диск. Bash может сохранять историю по своим настройкам, а отсоединённые через `nohup`/`disown` Unix-процессы могут продолжить работу.

`@types/vscode` закреплён на 1.97.0, `engines.vscode` = `^1.97.0`, Node >=18.17. Плагин не использует приватные команды Элемента, поэтому `xbsl.compatibility.basis` = `vscode-api-only`. Не объявляются непроверенные ветки server/IDE. Совместимость OS-функций и PTY остаётся ответственностью автора, независимо от решения marketplace.
