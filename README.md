# Терминал (Bash) для 1С:Предприятие.Элемент

Работайте с консольными командами рядом с кодом. Расширение добавляет Bash в нижнюю панель IDE Элемента: откройте терминал, запустите команду и продолжайте редактировать проект, пока она выполняется.

## Зачем устанавливать

- **Меньше переключений между окнами.** Выполняйте Git-команды, запускайте тесты, смотрите логи и работайте с файлами из IDE. Нужные утилиты должны быть установлены на сервере.
- **Начинайте с каталога проекта.** Новая сессия открывается в папке активного workspace. Для нескольких корневых папок можно выбрать нужную.
- **Разделяйте задачи по сессиям.** Держите сборку, просмотр логов и разовые команды в разных Bash-сессиях. Плагин позволяет открыть до восьми сессий.
- **Пользуйтесь привычной оболочкой.** История команд, Tab, Ctrl+C, ANSI-цвета и интерактивный ввод работают через псевдотерминал. Размер терминала меняется вместе с панелью.
- **Сохраняйте привычный интерфейс на разных ОС.** Одинаковые кнопки и сочетания клавиш, светлая и тёмная темы IDE. В пакет входят PTY-программы для Linux, Windows и macOS на x64 и arm64.

## Начало работы

Откройте палитру команд и выполните **«Терминал: Новый Bash»**. Появится вкладка **«Терминал» внизу IDE**. Сочетание клавиш: `Ctrl+Alt+Shift+T`, на macOS `Cmd+Alt+Shift+T`.

В панели выбирайте сессию из списка. Кнопка `+` открывает новую, ластик очищает экран, корзина завершает выбранную сессию. Для смены пути к Bash нажмите кнопку настроек или выполните **«Терминал: Выбрать Bash на сервере»**. Пустой путь включает поиск Bash.

```bash
pwd
git status
```

Команды выполняются **на сервере Элемента**, с правами учётной записи Node extension host. Плагин использует самостоятельный механизм процессов; executor для штатного терминала Элемента ему не нужен. Администратор должен разрешать такой доступ к консоли. Плагин не создаёт отдельную песочницу или пользовательскую изоляцию.

## Требования

| Среда сервера | Требование |
| --- | --- |
| Node extension host | Node.js 18.17 или новее; VS Code API, соответствующий `^1.97.0` |
| Linux x64 / arm64 | Ядро 3.2+, Bash и доступ к PTY (`/dev/ptmx`); также должны выполняться требования Node host |
| Windows x64 / arm64 | ConPTY: Windows 10 1809 / Server 2019 или новее; установленный Git Bash. При необходимости укажите полный путь к `bash.exe` |
| macOS x64 / arm64 | macOS 12+, установленный Bash; системный `/bin/bash` подходит |

На Windows используйте Bash из Git for Windows. Системный `bash.exe`, который запускает WSL, не подходит для этого способа запуска. На Windows arm64 используйте подходящую установку Git Bash; сочетание нативной архитектуры и эмуляции требует проверки на целевой машине.

Плагин выбирает PTY по ОС и архитектуре **серверного Node**, а не браузера. Настройку пути к Bash он читает из пользовательских настроек; значение из файлов workspace игнорирует. Bash загружает свои обычные пользовательские файлы запуска.

## Установка

Распакуйте `1c-xbsl-terminal-0.1.0-universal.zip`. Перенесите каталог `1c-xbsl-terminal-0.1.0` в согласованный каталог `/plugins` на сервере. Файл `package.json` должен находиться в корне каталога плагина. Затем перезагрузите IDE workspace штатным способом. Перезапуск сервера не требуется для самого копирования пакета.

## Разработка

Нужны Node.js, npm и Go 1.26.5. Для браузерного теста нужен Chrome.

```sh
npm ci --ignore-scripts
npm run build:helpers
npm run check
npm run build
npm test
npm run test:ui
npm run package
```

Результат сборки: каталог и ZIP в `release/`. Устройство процессов, границы API и протокол: [docs/architecture.md](docs/architecture.md).
